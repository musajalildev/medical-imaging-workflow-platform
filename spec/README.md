# Testing

This project uses automated RSpec tests to cover the main application behavior.

## Test types

### Controller specs

These test request/response behavior for the main controllers, including:

* Jobs
* Files
* Users
* Pages
* Notifications
* Reports
* Job status histories
* Complete jobs
* Cancelled jobs
* Image files
* Application-level behavior

They check things like:

* page loads
* redirects
* flash messages
* branching logic
* permission handling
* form submissions

### Model specs

These test model behavior such as:

* validations
* associations
* enums and roles
* helper methods

### Mailer specs

These test that emails are built with the correct:

* recipients
* subjects
* branching logic

### System specs

## External services

Some features depend on external services such as Google Drive and email delivery. These are stubbed or mocked in tests so the suite stays:

* repeatable
* fast
* safe to run locally and in CI

## Running the tests

Run the full suite with:

```bash
bundle exec rspec
```

Run one file with:

```bash
bundle exec rspec spec/controllers/jobs_controller_spec.rb
```

Run a single example with:

```bash
bundle exec rspec spec/controllers/jobs_controller_spec.rb:42
```

## Coverage

The test suite is designed to cover the core application flows and important branches in the controllers and models.

Current coverage can be generated by running the full suite. The SimpleCov report is written to the `coverage/` directory.

## Notes

A few specs use simplified stubs instead of full database or service integration. This keeps the tests stable while still covering the important controller branches.

There are also a few deprecation warnings about `:unprocessable_entity`. These do not fail the suite, but can be updated later to `:unprocessable_content`.
